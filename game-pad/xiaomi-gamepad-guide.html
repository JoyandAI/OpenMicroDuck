方案：板载用户态驱动

目标：让手柄真正控制机器人，而不是只看到“已连接”

小米蓝牙手柄一代是 Bluetooth 3.0 经典蓝牙，不是 BLE。它的规格页写的是“即插即用、无需驱动”，但那是针对小米电视/盒子；Linux 内核的通用 HID 映射会把 A/B/X/Y 和右摇杆弄错。因此本方案不直接使用内核原始节点，而是先装用户态驱动，把它变成标准标准虚拟手柄。

链路 板载直连

原手柄 → Radxa 蓝牙 → xiaomi-gamepad 用户态驱动 → 标准虚拟手柄 → padd → robotd。

为什么 用户态驱动

内核通用 HID 会把这只手柄的 A/B/X/Y 和右摇杆映射错；用户态驱动专门修正它，并隐藏错误节点。

最终“落地”的定义

安全提醒第一次测试必须让机器人趴在软垫上或由人扶住。不要把“先按一下试试”用在站立的整机上。
PART I · 只连手柄，不接机器人

先让手柄自己变成标准虚拟手柄

这一部分只使用板子、手柄和蓝牙。目标不是让机器人动，而是确认手柄在 Linux 下是一个干净、按键正确、右摇杆可用的标准虚拟手柄。此阶段不需要舵机、robotd、padd 或任何机器人装配。

你需要准备

  • 小米蓝牙手柄一代、2 节 AA 电池。先用碱性电池；不要用 3.7 V 14500。

先在 Mac 上设置板子地址

bash · Mac
BOARD=radxa@radxa-zero3.local

能看到 hostname 和内核版本即可。本部分不检查 robotd/padd，也不要求机器人上线。

板子上确认蓝牙和输入工具

bash · 板子
sudo systemctl status bluetooth --no-pager
command -v bluetoothctl
command -v evtest || sudo apt update && sudo apt install -y evtest joystick

没有网络装不了 evtest 也没关系，后面用 padd 日志判断；但没有蓝牙工具就不行。

02

配对到板子：先让 BlueZ 看见它

时间 15–20 分钟 · 板子终端 · 不接机器人
先确认终端下面的命令全部在 Radxa 板子的 SSH 终端里执行，不是在 Mac 上。Mac 没有 bluetoothctl。

1. 登录板子，启动蓝牙

bash · 板子
sudo systemctl start bluetooth
sudo rfkill unblock bluetooth
sudo bluetoothctl

看到 [bluetooth]# 提示符后，下面的命令都在这个提示符里输入。

2. 让手柄进入配对模式

按你原来配小米电视/手机的方式进入配对；如果有配对键就按配对键。指示灯应快速闪烁。不同批次组合不同，以灯快闪为准。

3. 扫描并找到 MAC

bluetoothctl
power on
agent on
default-agent
scan on

等待出现：

[NEW] Device XX:XX:XX:XX:XX:XX Xiaomi Gamepad

也可以用 devices 查看当前扫描结果。记下小米手柄的 MAC。

4. 关键：先 scan off，再配对

bluetoothctl
scan off

扫描不关，后面的 pair 可能一直返回 not available。先关扫描，再配对。

5. 配对、信任、连接

把下面四行的 MAC 全部换成你记下的真实地址：

bluetoothctl
pair XX:XX:XX:XX:XX:XX
trust XX:XX:XX:XX:XX:XX
connect XX:XX:XX:XX:XX:XX
info XX:XX:XX:XX:XX:XX

如果提示 PIN，先试 0000。输错就重新进入配对模式，不要反复试到锁定。

Device ... not available说明这个 MAC 当前不在 BlueZ 缓存里。回到 scan on，等 [NEW] Device 或 devices 出现，再 scan off → pair。不要连续 connect。

6. 确认已连接

info 应看到：

  • Name: 小米蓝牙手柄
  • Icon: input-gaming
  • Paired: yes、Trusted: yes
  • Connected: yes
  • LegacyPairing: no

然后退出：quit。

已经配对过，只是没连上

bash · 板子
sudo bluetoothctl connect XX:XX:XX:XX:XX:XX

扫描结果太多怎么办

先在 [bluetooth]# 里找 [NEW] Device ... 小米蓝牙手柄 或 Icon: input-gaming。不要为了过滤先退出配对流程。确实需要过滤时，scan off 后退出到普通 shell：

bash · 板子
bluetoothctl devices 2>&1 | grep -iE "xiaomi|gamepad|joystick|MDZ|手柄|小米"

也可以只看经典蓝牙：

bash · 板子
sudo hcitool scan
没看到设备？确认手柄灯在快闪；scan off 再 scan on；手柄不要同时连着手机/电视；换新 AA 电池。板子放在手柄旁边。
03

装驱动 + 键位验收：把乱码手柄变成标准虚拟手柄

时间 20–30 分钟 · Part I 的最后一关 · 不接机器人

小米一代的原始 HID 报告不是标准手柄布局。内核通用 HID 常见结果是：A/B/X/Y 错位、右摇杆不动、没有震动。这里不写新驱动，直接复用现成的开源用户态驱动。完成后手柄自己就是一个标准虚拟手柄，本部分到这里结束。

驱动做什么读取真实手柄的 /dev/hidrawN，用 EVIOCGRAB 抓住错误的内核节点，再通过 uinput 提供一个干净的 Microsoft X-Box 360 pad（045e:028e）。Part II 的 padd 会看到这个标准手柄。

项目地址：diegryllid/xiaomi_gamepad_linux，支持 VID/PID 2717:3144，MIT 许可。

1. 在板子上装依赖

bash · 板子
sudo apt update
sudo apt install -y python3-evdev evtest joystick git
sudo modprobe uinput
ls -l /dev/uinput

没有 /dev/uinput 时，先确认内核模块 uinput 存在；这是驱动创建虚拟手柄的必要条件。

2. 安装驱动

bash · 板子
cd ~
git clone https://github.com/diegryllid/xiaomi_gamepad_linux
cd xiaomi_gamepad_linux
sudo ./install.sh

安装脚本会放好 systemd 服务、udev 隐藏规则、uinput 模块加载配置。它是按需服务：手柄连上才启动。

板子不能访问 GitHub 时，在 Mac 上 git clone 后把整个目录 scp -r 到板子，再进目录执行 sudo ./install.sh。

3. 让手柄重新连接并验证

bash · 板子
sudo udevadm control --reload
sudo udevadm trigger --subsystem-match=hidraw --action=add
systemctl status xiaomi-gamepad --no-pager
journalctl -u xiaomi-gamepad -n 40 --no-pager

然后验证虚拟手柄：

bash · 板子
sudo python3 ~/xiaomi_gamepad_linux/tools/xiaomi-verify.py
grep -i -A6 'X-Box 360' /proc/bus/input/devices
虚拟手柄没出现时先看真实日志：sudo journalctl -u xiaomi-gamepad -b -n 80 --no-pager。还没有结果就停服务，前台跑一遍：sudo systemctl stop xiaomi-gamepad，再 sudo /usr/bin/python3 /usr/local/bin/xiaomi-gamepad.py。正常会依次打印 daemon started、pad found、virtual pad up。
不要用 by-id 判断uinput 创建的标准虚拟手柄 通常不会出现在 /dev/input/by-id/，所以那里没有该设备是正常的。用 /proc/bus/input/devices 或 xiaomi-verify.py 判断。

按每个键，脚本应打印对应的控制。看到 Microsoft X-Box 360 pad 才算成功。

Part I 完成如果 A/B/X/Y、十字、L1/R1、L2/R2、左右摇杆、Start/Select 都能逐项打印，按 Ctrl+C 退出验证脚本，保持 xiaomi-gamepad 服务运行。Part II 重启 padd，做服务联动。
journalctl 要加 sudo不加 sudo 时，journalctl -u xiaomi-gamepad 可能只显示 No entries，因为服务是 root 跑的。用 sudo journalctl -u xiaomi-gamepad -b -n 80 --no-pager 看真实日志。
UInput max_effects 报错如果日志出现 UInput.__init__() got an unexpected keyword argument 'max_effects'，是板上的 python-evdev 不支持这个参数，不是手柄问题。备份后删掉该参数并重启：
sudo cp /usr/local/bin/xiaomi-gamepad.py /usr/local/bin/xiaomi-gamepad.py.bak
sudo sed -i "s/, max_effects=16//" /usr/local/bin/xiaomi-gamepad.py
sudo systemctl restart xiaomi-gamepad

检查期望

5. 震动 / 保活（正常现象）

这只手柄只在输入变化时上报；空闲时链路会静默，约 2 分钟后可能 Input/output error 断连。驱动必须周期性写 0x20 01 01 保活。

持续轻微嗡嗡响是正常的保活包会驱动马达，所以空闲时手柄会持续轻微嗡嗡响。这不是驱动故障，也不是电池问题，是保活的副作用。

如果驱动被改过，保持原逻辑即可：

python · 原保活
RUMBLE_STOP = bytes([0x20, 0x01, 0x01])
KEEPALIVE_S = 2.0

# 空闲时每 KEEPALIVE_S 发一次 RUMBLE_STOP
不要这样改不要把保活包改成 0x20 00 00（会关机），也不要完全关闭 keepalive（约 2 分钟就掉线）。目前没有“既安静又永久在线”的软件包。

如果无法接受嗡嗡声，只能二选一：

  • 拆掉手柄震动马达，继续用 0x20 01 01 保活；
  • 接受空闲约 2 分钟自动关机，需要时重新开机。
电池原作者明确记录：弱 AA 电池 + 马达启动电流会让这只手柄“假死/掉线”。测试用新碱性电池或低内阻 NiMH，并且不要开震动。

接入机器人：padd 服务联动

时间 30–45 分钟 · 从这里才开始用机器人 · 先支撑/卸力
PART II 开始机器人必须在软垫上或由人扶住，舵机不上力；先确认手柄已经被 padd 看到，再谈驾驶。任何“让它走一下试试”都必须等站立和急停测试完成。
先纠正一个误区当前 padd 使用内置映射，不读额外映射文件，也没有独立的映射页面。手柄只要变成标准虚拟手柄 并被 padd 看到，就已经接入了机器人服务。

确认服务联动

bash · 板子
systemctl is-active xiaomi-gamepad padd
systemctl is-enabled xiaomi-gamepad
sudo journalctl -u padd -n 30 --no-pager | \
  grep -E "pad connected|pad gone"

必须看到：

  • xiaomi-gamepad 和 padd 都是 active
  • xiaomi-gamepad 是 enabled，重启后仍会启动
  • padd 日志出现 pad connected — driving pad="Xbox 360 Controller"

如果服务是 static 或重启后不启动，创建启动链接：

bash · 板子
sudo mkdir -p /etc/systemd/system/multi-user.target.wants
sudo ln -sf /etc/systemd/system/xiaomi-gamepad.service \
  /etc/systemd/system/multi-user.target.wants/xiaomi-gamepad.service
systemctl is-enabled xiaomi-gamepad

只保留一个输入源

  • 断开其他蓝牙手柄、网页虚拟手柄。
  • 只让小米手柄连接板子；padd 只应看到标准虚拟手柄。
  • 不要同时开 evtest 和 padd。

05

安全驾驶：先站起来，再走 1 米

时间 20–30 分钟 · 软垫 / 空旷地面 · 人站在旁边
  1. 机器人放平，周围 1 m 清空；手柄握在手里，先不要碰摇杆。
  2. 按 Start：第一下回 HOME；等机器人站稳，再按第二下启用策略。
  3. 轻推左摇杆 Y，确认前进方向；如果反了，先停下检查，不要靠“习惯反着推”。
  4. 轻推左摇杆 X，确认横移方向；再推右摇杆 X，确认转向方向。
  5. 先用 0.10 m/s、转向 0.5 rad/s，走 1 m，停。
  6. 摇杆回中，确认机器人能停住，不会继续走。
速度不要一次拉满默认上限约 0.30 m/s / 1.5 rad/s。第一阶段只用 1/3，确认方向、死区、刹车都正常。

如果方向正确、能停、无抖动，才进入物理断电测试。

06

deadman、掉线、物理断电：先把最坏情况测掉

时间 20–30 分钟 · 软垫 / 空地 · 不做技能

1. Deadman 和断线

轻推摇杆走起来，然后松手回中。机器人应在 deadman 窗口内停止/减速，不能持续走。测试 5 次。

机器人站立，直接关掉手柄电源。应在约 1–1.5 秒内自动坐下或停止；重新开手柄，确认能回连。测试 3 次。

2. Select 是关机，不是急停

长按 Select 2 秒会关机。不要把它当急停键，也不要在机器人行走时测试。急停测试用物理断电：手边保持电池插头/总开关能一手断开。

3. 随机输入

机器人站立，随机按 100 次（不要按 A/B/Y/L1/R1 技能键，不要让它走）。确认不出现未预期的模式/技能。

测试通过标准结果
Deadman松手后 0.5 s 左右停止
关手柄1–1.5 s 内坐下/停止，不冲
重连开机自动回连，不重复配对
随机输入无未绑定技能触发
物理断电一手能断，断后不冲
物理急停软件里没有独立的“Select 急停”。最后一道保险始终是电池插头/电源开关；测试时人不要站在机器人正前方。

先说明：padd 使用内置映射，没有额外的绑技能页或映射文件。下面按当前日志里的实际语义逐个验证，不要按手柄字母猜。

现有机器人默认语义

  • 左摇杆：前进 / 后退 / 横移；右摇杆左右：转向。
  • Start：切换策略 / 站立。
  • Y：头部模式；B：身体姿态；A：地面捡起。
  • L1 / R1：左 / 右踢；L2 / R2：嘴开合。
  • 十字键下：坐下；十字键上 3 秒：walk / roller 切换。
  • Select 长按 2 秒：关机，不是急停。
  • X、Home / Mi：不绑定。
  • 断手柄约 1 秒：机器人停止；deadman 约 500 ms。

风险表

风险概率处理
内核 HID 映射错 / 右摇杆死高安装 xiaomi-gamepad 用户态驱动，不要用原始节点
按键映射和手柄丝印不一致中按 evtest 原始码重绑，不看字母

技能键误触中A/B/Y/L1/R1 最后逐个验证
AA 电池低电导致掉线中新碱性电池；关震动；关手柄自动坐下
蓝牙 2.4G 干扰中缩短距离、换 Wi-Fi 信道、靠近板子

回滚

bash · 板子
sudo systemctl stop padd
sudo systemctl stop xiaomi-gamepad
sudo systemctl disable xiaomi-gamepad

要恢复时重新 systemctl enable --now xiaomi-gamepad，再启动 padd。

完成标志手柄只负责“意图”，robotd 仍然负责 deadman、限速和安全。你不需要为了手柄改控制核心；能把标准 HID 事件稳定映射到 padd，就已经落地。

本手册按 2026-11-12 的机器人软件与小米手柄一代规格整理。具体 padd / 镜像版本不同，按键语义可能有差异；以 padd 日志里的 driving 行和实际动作为准。
